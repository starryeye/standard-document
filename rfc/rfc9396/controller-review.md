# RFC 9396 공개판 교정 검수

[공식 영문](https://datatracker.ietf.org/doc/html/rfc9396) · [독립 읽기판](./) · [블로그 전문](https://starryeye.github.io/rfc/rfc9396/) · [공개판 무결성 기록](publication.json)

2023년 5월 발행본과 이미 승인된 한국어 읽기판을 바탕으로 공개판의 교정 구간을 다시 원문과 비교했다. 번역 전체를 다시 생성하지 않았다. 원문 발행본의 고정 캡처 SHA-256은 `86dd1023d3957c878c155a1d12a4bb4911c139c2f2f7551823c5e92713550f15`, [기존 승인 읽기판](reviewed.html)은 `03f38bcb1c98bee8b16744cb850322b23850954a546a471f0f1ecd9147e656d2`다.

- [§7](https://datatracker.ietf.org/doc/html/rfc9396#section-7-3): 상세 인가 정보에서 일부 값을 생략하는 것은 AS의 선택이다. 필요성을 별도 전제로 두지 않았다.
- [§7.1](https://datatracker.ietf.org/doc/html/rfc9396#section-7.1-7): 의료 기록 예시에서 client는 요청 당시 기록 번호를 알지 못한다. 위치·식별자를 지정하지 않는다는 다음 설명도 그대로다.
- [§12](https://datatracker.ietf.org/doc/html/rfc9396#section-12-1): 무결성을 고려해야 하는 경우의 보호 의무를 유지했다. 가능한 보호 방식이나 관련 인용은 변경하지 않았다.
- [§13](https://datatracker.ietf.org/doc/html/rfc9396#section-13-3): 가능한 경우 인증을 마친 뒤, 현재 사용자 맥락이 처음에 가정한 맥락과 같은지 확인하도록 순서를 분명히 했다. 대응 필요성과 두 가지 예시의 선택 관계는 그대로다.

원문의 규범 키워드 강조 34곳과 날짜 속성 19개를 같은 위치에 맞췄고, 저자 3인의 연락처 사이에 여백을 확보했다. 네 문구와 두 종류의 마크업 변경만 되돌리면 기존 승인 본문과 바이트 단위로 같음을 확인했다. HTML의 원문 링크·앵커와 JSON·HTTP 예제 30개의 공백·줄바꿈을 보존했다. [기존 산출물 검토 기록](review-report.md)은 승인본의 기록이므로 고치지 않았다.

배포 전 블로그와 독립 읽기판 미리보기를 1440·768·390px에서 각각 검수했다. 교정 문구·규범어 굵기·연락처 간격·열린 문서 정보와 목차를 실제로 확인하고, 목차 링크 46개의 대상, 영문 저작권 고지, 코드 상자의 스크롤 및 화면 자체의 넘침 여부를 검사했다. 두 사이트는 동일한 교정 본문(`c5eedb5cc091c0917acb66335cb514a4898707c8b2c45f99081a49db9cf7ebea`)을 사용한다.
