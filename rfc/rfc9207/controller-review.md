# RFC 9207 원문 대조 및 공개판 검수

[IETF 영문 발행본](https://datatracker.ietf.org/doc/html/rfc9207) · [독립 읽기판](index.html) · [블로그](https://starryeye.github.io/rfc/rfc9207/)

2022년 3월의 발행본과 한국어 읽기판을 초록부터 저자 연락처까지 직접 대조했다. 응답 `iss`, 메타데이터 `issuer`, ID Token/JARM의 `iss`를 구분했다. 디코딩 후 단순 문자열 비교, 값 불일치에 대한 응답 거부와 인가 중단, 서버가 지원을 표시했는지에 따른 누락 처리, 대체 수단의 적용 조건을 확인했다.

공개판에는 독립 검토에서 지적된 변경만 적용했다.

- §2.4 첫 문단: 수신 응답에 `iss`가 있을 경우에 값을 추출한다는 점을 규칙으로 명시했다. 값이 없는 경우의 수락 여부나 차후 비교 규칙은 바꾸지 않았다.
- §2.4의 RFC 6749 참조 문단: 미지원 client가 인식하지 못하는 `iss`를 **무시해야 한다**는 의무가 분명하도록 문장을 나눴다.
- 원문의 규범 키워드 강조 36곳, 날짜 `datetime` 속성 14개를 원래 위치에 복원하고 두 저자의 연락처 사이에 여백을 추가했다. 성공·오류 HTTP 예제 두 개는 내용과 줄바꿈까지 원문과 동일하다.

교정한 위치를 원문과 다시 비교하고, 두 사이트의 1440·768·390px 미리보기에서 강조·연락처·목차 이동·문서 정보·원문 표·모바일 예제의 양쪽 끝을 확인했다. 본문 조각은 두 사이트에서 동일하며, 수정한 위치 외에 승인된 문구·링크·앵커는 바꾸지 않았다. 좁은 화면에서 긴 식별자가 줄바꿈될 수 있으며 문자열은 그대로다.

[수정 전 승인 읽기판](reviewed.html), [승인 본문](article.html), [기존 검수 manifest](manifest.json)는 변경하지 않았다. [publication.json](publication.json)은 별도 공개본과 추가 스타일의 해시를 기록한다. 이 페이지는 비공식 AI 한국어 번역이며 해석의 기준은 IETF 공식 영문이다.
